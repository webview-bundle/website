---
title: '원격 업데이트'
---

원격 업데이트(OTA, Over the Air)는 네이티브 앱을 다시 빌드하지 않고 웹뷰 번들을
교체하는 기능입니다.

## 업데이트 흐름

웹 빌드 결과를 번들로 업로드하고, 배포로 해당 버전을 공개한 뒤, 클라이언트에서
다운로드하고 설치합니다.

![웹 리소스 빌드, .wvb 파일 업로드, 업데이트 배포, 클라이언트 조회·다운로드·설치 순서로 진행합니다.](/diagrams/remote-workflow.svg)

### 번들 업로드

프론트엔드를 빌드한 뒤 정적 결과물을 번들 이름과 버전에 맞춰 패키징하고
업로드합니다. `.wvb` 바이트의 무결성 해시를 함께 저장할 수 있습니다.

### 버전 배포

릴리즈 준비가 되면 업로드한 버전을 배포합니다. 제공자는 번들 버전과 무결성
메타데이터를 담은 업데이트 정보를 만들고, 해당 런타임·채널이 가리키는 현재
업데이트를 바꿉니다.

배포 시 업데이트 정보를 서명하고 클라이언트에서 이를 검증할 수 있습니다. 이는
신뢰하지 못한 출처의 업데이트 정보를 참조하는 것을 방지하고 업데이트 모델의
보안을 높일 수 있습니다. 자세한 내용은
[서명 요구사항](/docs/guide/remote/spec#서명)을 참고하세요.

### 다운로드와 설치

클라이언트는 업데이트 정보를 조회하고 필요한 번들을 확인한 뒤 해당 버전을
다운로드합니다. 다운로드한 번들은 설치 대기 상태로 저장됩니다. 설치하면 해당
버전을 활성화합니다.

업데이트 확인과 UI 새로고침 시점은 앱에서 정합니다. 새로고침 전에 번들별
다운로드·설치 결과를 확인하세요. 업데이터는 이전 리모트 버전으로 되돌리는 명시적
롤백 기능을 제공합니다.

## 리모트 서버 구성

AWS 제공자는 S3, CloudFront, Lambda@Edge를 사용합니다. Cloudflare 제공자는 R2,
Workers, KV를 사용합니다.

서버 생성은 [제공자](/docs/guide/remote/provider)를 참고하세요. 서버를 직접
구현하려면 [리모트 기술 사양](/docs/guide/remote/spec)을 따르세요.
