---
title: '웹뷰 번들 (.wvb)'
---

`.wvb` 파일은 웹 리소스와 HTTP 응답 메타데이터를 함께 저장합니다. 네이티브
호스트가 읽는 데이터와 설치된 버전의 선택 방식을 설명합니다. 번들 생성과 실행
절차는 플랫폼별 가이드를 참고하세요.

## 데이터 구조

포맷은 헤더, 인덱스, 개별 압축한 리소스 데이터로 구성됩니다. 헤더는 인덱스의
크기를, 각 인덱스 항목은 리소스의 위치를 나타냅니다.

![헤더와 인덱스에 체크섬이 있습니다. 데이터 영역의 압축한 리소스마다 별도의 체크섬이 있습니다.](/diagrams/wvb-structure.svg)

### 헤더

헤더는 처음 17바이트를 차지합니다. 매직 값 8바이트(`0xF09F8C90F09F8E81`, 🌐🎁을
UTF-8로 인코딩), 포맷 버전 1바이트(`1`), 인덱스 크기 4바이트, 앞의 13바이트에
대한 xxHash-32 체크섬 4바이트로 구성됩니다. 빅 엔디언 순서로 저장합니다.

인덱스 크기에는 인덱스의 4바이트 체크섬이 포함되지 않습니다.

### 인덱스

인덱스는 각 리소스 경로를 데이터 영역의 오프셋과 압축된 길이에 연결합니다.
항목에는 콘텐츠 유형, 원본 길이, 선택적인 HTTP 응답 헤더도 포함됩니다. 경로를
정렬해 직렬화하며, 인덱스 뒤에 xxHash-32 체크섬 4바이트를 저장합니다.

![요청 경로로 인덱스를 조회해 리소스의 오프셋과 길이를 찾습니다.](/diagrams/wvb-index-lookup.svg)

인덱스 데이터는 [bincode](https://sr.ht/~stygianentity/bincode/)를 사용하여
직렬화/역직렬화 합니다.

### 데이터

각 리소스를 [LZ4](https://github.com/lz4/lz4)로 개별 압축하고 압축 해제 후 크기
필드를 앞에 붙입니다. 압축한 항목마다 뒤에 xxHash-32 체크섬 4바이트를
저장합니다. 읽기 작업은 인덱스의 오프셋으로 이동해 항목을 읽고 검증한 뒤 해당
리소스의 압축을 해제합니다.

오프셋이 `0`, 길이가 `768`인 항목이라면 데이터 영역 기준 `0`부터 `767`까지가
페이로드입니다. 그다음 4바이트에 해당 항목의 체크섬이 있습니다.

## 왜 새로운 포맷을 만들었나요?

웹뷰 번들은 요청 경로를 조회하고 HTTP 메타데이터와 함께 리소스를 반환하는 데
초점을 맞췄습니다. 단순한 공통 포맷은 여러 네이티브 플랫폼에서 읽기 동작을
구현하고 유지하는 데도 도움이 됩니다.

주요 특성은 다음과 같습니다:

- **임의 접근:** 인덱스 조회로 필요한 리소스의 바이트 범위를 찾습니다.
- **HTTP 응답에 필요한 정보:** 콘텐츠 유형과 응답 헤더를 리소스와 함께
  보관합니다.
- **낮은 압축 해제 비용:** 압축 해제가 빠른 [LZ4](https://github.com/lz4/lz4)를
  사용합니다. 리소스를 로컬에서 읽으므로, 아카이브 크기를 줄이는 것보다 접근과
  압축 해제 비용을 우선합니다.

## 소스

소스는 기기에 저장한 번들을 관리합니다. **빌트인** 번들은 네이티브 앱에 포함하며
읽기 전용으로 사용합니다. **리모트** 번들은 쓰기 가능한 앱 저장소에 원격으로부터
다운로드합니다.

활성화된 리모트 버전은 빌트인 버전보다 우선합니다. 다운로드만 완료한 버전은 설치
전까지 활성화되지 않습니다. 활성 리모트 버전이 없으면 빌트인 버전을 선택합니다.

자세한 리모트 번들의 사용법은 [릴리즈](/docs/guide/releasing) 문서를 참고하세요.

### 디스크 레이아웃

빌트인과 리모트 디렉터리는 각각 매니페스트와 번들별 디렉터리를 가집니다. `app`
번들의 두 버전을 저장한 구조는 다음과 같습니다:

<Files>
  <Folder name="bundles" defaultOpen>
    <File name="manifest.json" icon={<IconJson />} />
    <Folder name="app" defaultOpen>
      <File name="1.0.0.wvb" />
      <File name="1.1.0.wvb" />
    </Folder>
  </Folder>
</Files>

경로는 `SOURCE_DIR/BUNDLE_NAME/VERSION.wvb`입니다. `SOURCE_DIR`은 빌트인 또는
리모트 디렉터리, `BUNDLE_NAME`은 번들 이름, `VERSION`은 버전으로 바꿉니다.

### 매니페스트

매니페스트는 저장된 버전과 활성 상태를 기록합니다. 다음 예제는 `1.0.0`을
사용하며 `1.1.0`의 설치를 준비한 상태입니다:

```json title="manifest.json"
{
  "manifestVersion": 1,
  "bundles": {
    "app": {
      "versions": { "1.0.0": {}, "1.1.0": {} },
      "currentVersion": "1.0.0",
      "stagedVersion": "1.1.0"
    }
  }
}
```

번들별로 기록하는 상태는 다음과 같습니다:

- `versions`: 저장된 버전과 선택적인 `integrity`, 문자열
  해시값(`HashMap<string, string>{:rust}`)으로 구성된 `metadata`입니다.
- `currentVersion`: 활성 버전입니다.
- `previousVersion`: 롤백에 사용할 이전 활성 버전입니다.
- `stagedVersion`: 다운로드를 완료하고 설치를 기다리는 버전입니다.

소스는 현재·이전·설치 대기 상태에 필요한 버전을 보관합니다. 상태 변화는
[원격 업데이트](/docs/guide/concepts/remote)를 참고하세요.
