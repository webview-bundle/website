title: '네이티브 측 구현'

웹뷰 번들 포맷을 각 플랫폼별로 사용하기 위해서, 네이티브에서 어떤 방식으로
통합하였는지 설명합니다.

## Rust로 작성한 코어

Rust로 작성된 코어([wvb](https://crates.io/crates/wvb))는 `.wvb` 파일 읽기,
빌트인·리모트 소스 관리, 리소스 요청 처리, 업데이트 다운로드·설치를 담당합니다.
이 로직을 공유해 호스트마다 포맷을 읽고 버전을 선택하는 방식을 일관되게
유지합니다.

## 멀티 플랫폼·환경 지원

각 통합은 다음 인터페이스로 코어를 호출합니다:

| 호스트             | 코어 호출 방식           | 웹뷰 연동                             |
| ------------------ | ------------------------ | ------------------------------------- |
| Node.js / Electron | napi-rs 네이티브 모듈    | Electron 프로토콜과 preload 통신      |
| Tauri              | Rust 크레이트            | Tauri 플러그인과 사용자 정의 URI 스킴 |
| Android            | UniFFI Kotlin 바인딩     | `WebViewClient` 요청 가로채기         |
| iOS                | UniFFI Swift 바인딩      | `WKURLSchemeHandler`                  |
| Deno Desktop       | Deno FFI 공유 라이브러리 | `Deno.serve()`로 제공하는 라우트      |

## 프로토콜 핸들링

`app://app.wvb/index.html` 요청에서 기본 번들 해석기는 호스트의 첫 번째 부분인
`app`을 번들 이름으로 사용하고, 경로 해석기는 `/index.html`을 선택합니다.
네이티브에서는 해당 항목의 데이터, 콘텐츠 유형, 헤더를 웹뷰 번들에서 읽어 웹뷰에
HTTP 응답합니다.

### 번들 해석기 (`UriBundleResolver`)

- `hostname` : URI의 hostname을 사용합니다.
  - `segment` : Hostname에서 사용할 segment의 유형 혹은 n번째 값 입니다.
    (기본값: first)
  - `allowWvbSuffixOnly` : Hostname이 `.wvb`로 끝나는 경로에 대해서만
    허용합니다. (기본값: false)
- `pathname` : URI의 pathname을 사용합니다.
  - `segmentIndex` : Pathname에서 몇 번째 segment을 사용할지 여부 (기본값: 0)

```typescript
import type { UriBundleResolver } from '@wvb/node';

// `https://app.wvb/index.html` -> bundle "app"
const byHostname: UriBundleResolver = { type: 'hostname' };

// `https://cdn.example.com/my-app/index.html` -> bundle "my-app"
const byPathname: UriBundleResolver = { type: 'pathname', segmentIndex: 0 };
```

### 경로 해석기 (`UriPathResolver`)

- `exact` : URI의 pathname 그대로 사용합니다.
- `directory_index` : 확장자가 없는 경로에 대해 `/index.html` 을 붙입니다.
  - 예: `/` -> `/index.html`, `/about` -> `/about/index.html`
  - 정적 사이트 혹은 MPA(Multi Page Application) 스타일
  - Astro의 `format: 'directory'{:js}`, Next.js의 `trailingSlash: true{:js}`
    옵션과 동일한 동작입니다.
- `html_extension` : 확장자가 없는 경로에 대해 `.html` 확장자를 붙입니다.
  - 예: `/` -> `/index.html`, `/about` -> `about.html`
  - Astro의 `format: 'file'{:js}`, Next.js의 `trailingSlash: false{:js}` 옵션과
    동일한 동작입니다.

---

개발 중에는 프록시 핸들러가 HTTP 요청을 프론트엔드 서버로 전달합니다. 배포한
앱에서는 번들 핸들러가 로컬 리소스를 읽습니다.

| 통합         | 개발 서버                       | 번들 리소스                      |
| ------------ | ------------------------------- | -------------------------------- |
| Electron     | `proxyProtocol()`               | `bundleProtocol()`               |
| Tauri        | `ProtocolConfig::proxy()`       | `ProtocolConfig::bundle()`       |
| Android      | `WebViewBundleProtocol.local()` | `WebViewBundleProtocol.bundle()` |
| iOS          | `.local(scheme:hosts:)`         | `.bundle(scheme:)`               |
| Deno Desktop | `{ proxy: URL }` 라우트         | `{ bundle: NAME }` 라우트        |

### Android, Deno Desktop 프로토콜

Android는 `http` 또는 `https` 프로토콜을 사용합니다. Android WebView는 커스텀
URL 스킴의 리소스 요청과 링크 해석에 제약을 둡니다. 웹 표준 기능과의 호환성을
유지하기 위해, 번들 리소스도 동일 출처 정책과 호환되는 HTTP(S) URL로 제공합니다.
자세한 내용은 Android의
[커스텀 URL 처리](https://developer.android.com/develop/ui/views/layout/webapps/webview#handling-custom-urls)와
[앱 내 콘텐츠 로드](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content)를
참고하세요.

Deno Desktop은 제공하는 API에 맞춰 `Deno.serve()`의 라우트 기반으로 요청을
처리합니다. 라우트 설정에서 사용할 번들을 선택하고, 요청 URL의 `pathname`으로
번들 내부의 리소스 경로를 해석합니다.
