기존 Electron 앱에 웹뷰 번들을 연결합니다. 먼저 프론트엔드 개발 서버를 불러온
뒤, 같은 창에서 빌트인 번들을 실행합니다. 마지막으로 Forge와 electron-builder
패키징을 설정합니다.

## 시작 전 준비

Electron 15 이상과 Node.js 20.19 이상인 20.x 또는 22.12 이상을 준비하세요. 메인
프로세스를 빌드하고 실행할 수 있는 Electron 프로젝트에서 시작합니다.
프론트엔드는 `web`, 정적 빌드 결과는 `web/dist`에 배치합니다. 명령은 Electron
프로젝트 루트에서 실행하세요.

이 가이드의 파일 구조는 다음과 같습니다:

## 2. 인스턴스 생성과 개발 서버 연결

Electron이 준비되기 전에 메인 프로세스 진입점에서 인스턴스를 생성하세요. `app`
스킴에 `proxyProtocol`을 등록하고, `ready()`가 완료된 후 창을 여세요:

```ts title="src/main.ts"
import { BrowserWindow } from 'electron';
import { proxyProtocol, webviewBundle } from '@wvb/electron';

const wvb = webviewBundle({
  protocols: [
    proxyProtocol('app', {
      hosts: { 'app.wvb': 'http://localhost:5173' },
    }),
  ],
});

wvb.ready().then(async () => {
  const win = new BrowserWindow({
    webPreferences: {
      contextIsolation: true,
      nodeIntegration: false,
    },
  });
  await win.loadURL('app://app.wvb/');
});
```

프론트엔드 개발 명령으로 `http://localhost:5173` 서버를 시작하고 Electron 앱을
실행하세요. `app://app.wvb/` 요청을 해당 서버로 전달합니다. `hosts`의
`app.wvb`는 요청의 전체 호스트 이름과 일치해야 합니다.

<Callout title="proxyProtocol의 HMR 연결">
`proxyProtocol`은 커스텀 스킴의 HTTP 요청을 전달합니다. HMR을 지원하는 개발
서버에서 사용시에 정상적으로 WebSocket 서버에 연결이 힘들 수 있습니다. 이 경우,
개발 서버의 연결 주소를 명시하여 클라이언트에서 WebSocket 서버에 정상 접속하도록
할 수 있습니다.

[Vite](https://vite.dev)를 사용하는 경우 다음과 같습니다.

```typescript title="vite.config.ts"
import { defineConfig } from 'vite';

export default defineConfig({
  server: {
    port: 5173,
    strictPort: true,
    ws: {
      protocol: 'ws',
      host: 'localhost',
      clientPort: 5173,
    },
  },
});
```

</Callout>

## 4. 로컬 빌드 결과를 빌트인으로 설치

웹 워크스페이스의 `dist` 디렉터리를 `app` 번들, `1.0.0` 버전으로 패키징하도록
설정하세요:

```ts title="web/wvb.config.ts"
import { defineConfig } from '@wvb/cli';

export default defineConfig({
  pack: {
    srcDir: './dist',
  },
  remote: {
    bundleName: 'app',
    version: '1.0.0'
  },
});
```

네이티브 프로젝트 루트에서 `builtin.target`이 웹 워크스페이스를 가리키도록
설정하세요:

```ts title="wvb.config.ts"
import { defineConfig } from '@wvb/cli';

export default defineConfig({
  builtin: {
    target: {
      type: 'local',
      workspaces: ['./web'],
    },
  },
});
```

프론트엔드의 기존 빌드 명령을 실행하세요. `web/dist/index.html`이 생성되면
네이티브 프로젝트 루트에서 다음 명령을 실행하세요:

```sh
yarn wvb builtin
```

CLI는 웹 빌드 결과를 패키징하고 `./.wvb/builtin/bundles/manifest.json`과
`./.wvb/builtin/bundles/app/1.0.0.wvb`를 생성합니다.

## 5. 빌트인 번들 실행과 확인

`src/main.ts`의 `proxyProtocol` import를 `bundleProtocol`로 바꾸세요.
`protocols` 배열은 다음과 같이 교체하세요:

```ts
import { BrowserWindow } from 'electron';
import { proxyProtocol, webviewBundle } from '@wvb/electron'; // [!code --]
import { bundleProtocol, webviewBundle } from '@wvb/electron'; // [!code ++]

const wvb = webviewBundle({
  protocols: [
    proxyProtocol('app', { // [!code --]
      hosts: { 'app.wvb': 'http://localhost:5173' }, // [!code --]
    }), // [!code --]
    bundleProtocol('app'), // [!code ++]
  ],
});

wvb.ready().then(async () => {
  const win = new BrowserWindow({
    webPreferences: {
      contextIsolation: true,
      nodeIntegration: false,
    },
  });
  await win.loadURL('app://app.wvb/');
});
```

프론트엔드 서버를 종료하고 Electron을 다시 실행하세요. `app://app.wvb/`에서 같은
화면이 표시되어야 합니다.

## 6. 앱  패키징

빌트인 번들과 함께 앱을 패키징하기 위해 다음과 같은 과정을 진행해주세요.

<Callout title="패키징 시에 `node_modules`가 디스크에 존재해야 합니다.">
Electron 앱을 패키징할 때 프로젝트의 `node_modules` 디렉터리를 탐색하여 번들로 포함할 의존성들을 수집합니다.
이 때 사용되는 모듈 해석 알고리즘은 심볼링 링크로 연결된 의존성이나 Yarn의 Plug'n'Play(PnP) 포맷은 동작하지 않습니다.

- Yarn 2 버전 이상을 사용 중이라면, `.yarnrc.yml` 에서 `nodeLinker: node-modules`로 설정해 주세요.
- pnpm을 사용 중이라면, `.npmrc` 설정 파일에 `node-linker=hoisted`를 추가해 주세요.
</Callout>

### 패키징 스크립트 작성

`@electron/packager` API를 이용해 Electron 앱을 패키징하는 스크립트를 작성합니다.
`node package.mts` 커맨드를 실행해 패키징을 수행해요.

```typescript title="package.mts"
import { packager } from '@electron/packager';

const electronPkg = await import('electron/package.json', {
  with: {
    type: 'json',
  },
});

const [appDir] = await packager({
  dir: '.',
  out: './out',
  overwrite: true,
  // import only 'dist', 'node_modules', and 'package.json'
  ignore: [/^\/(?!(?:dist|node_modules)(?:\/|$)|package\.json$)/],
  electronVersion: '45.0.0',
  name: 'MyWebviewBundleApplication',
  asar: {
    unpack: `**/*.${process.platform}-*.node`,
  },
  extraResource: ['./.wvb/builtin/bundles'],
});

console.log(appDir);
```

</Step>

<Step>
### 배포용 파일로 만들기

패키징된 앱을 배포용 파일로 만들기 위해 각 플랫폼 별 도구를 사용해야합니다.
자세한 내용은 [Distributing Apps With Electron Forge](https://www.electronjs.org/docs/latest/tutorial/forge-overview) 가이드 문서를 확인하세요.

아래 예제는 macOS에서 `.dmg` 파일로 만드는 방법을 가이드합니다.

```typescript title="make.mts"
import path from 'node:path';
import fs from 'node:fs/promises';
import { exec } from 'es-toolkit/server';

const appPath = path.join(
  import.meta.dirname,
  'out',
  `MyWebviewBundleApplication-${process.platform}-${process.arch}`,
);
const dmgSrc = path.join(import.meta.dirname, 'out', 'dmg');

await fs.rm(dmgSrc, { recursive: true, force: true });
await fs.mkdir(dmgSrc, { recursive: true });
await fs.cp(
  path.join(appPath, 'MyWebviewBundleApplication.app'),
  path.join(dmgSrc, 'MyWebviewBundleApplication.app'),
  {
    recursive: true,
    verbatimSymlinks: true,
  },
);
await fs.symlink('/Applications', path.join(dmgSrc, 'Applications'));

const dmgPath = path.join(import.meta.dirname, 'out', `MyWebviewBundleApplication.dmg`);
await fs.rm(dmgPath, { force: true });
await exec('hdiutil', [
  'create',
  '-volname',
  'MyWebviewBundleApplication',
  '-srcfolder',
  dmgSrc,
  '-format',
  'UDZO',
  '-ov',
  dmgPath,
]);
```

이후 앱을 코드 서명하는 가이드는 Electron 공식 문서, [Code Signing](https://www.electronjs.org/docs/latest/tutorial/code-signing)을 확인해주세요.

</Step>
</Steps>

## Electron Forge

웹뷰 번들을 [Electron Forge](https://www.electronforge.io/)와 함께 사용하기 위한 플러그인 사용법을 가이드합니다.

[`@wvb/electron-forge`](/docs/references/api/electron-forge)를 사용하면 웹뷰 번들 빌트인 번들을 앱 리소스에 복사할 수 있습니다.

<Tabs items={["npm", "yarn", "pnpm"]}>
  <Tab value="npm">
    ```sh
    npm install --save-dev @wvb/electron-forge
    ```
  </Tab>
  <Tab value="yarn">
    ```sh
    yarn add -D @wvb/electron-forge
    ```
  </Tab>
  <Tab value="pnpm">
    ```sh
    pnpm add -D @wvb/electron-forge
    ```
  </Tab>
</Tabs>


이후 Forge 설정에서 `new WebviewBundlePlugin(){:js}`을 추가해주세요.

```ts title="forge.config.ts"
import type { ForgeConfig } from '@electron-forge/shared-types';
import { AutoUnpackNativesPlugin } from '@electron-forge/plugin-auto-unpack-natives';
import { WebviewBundlePlugin } from '@wvb/electron-forge';

const config: ForgeConfig = {
  packagerConfig: {
    asar: true,
  },
  plugins: [new AutoUnpackNativesPlugin({}), new WebviewBundlePlugin()],
};

export default config;
```

패키징한 앱에 `@wvb/electron`과 네이티브 바인딩 파일을 포함하세요. 메인
프로세스를 번들러로 빌드한다면 `@wvb/electron`을 external로 지정해 런타임 파일을
유지하세요.

Vite를 사용한다면 다음과 같이 설정할 수 있습니다:

```ts title="vite.main.config.ts"
import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    rolldownOptions: {
      external: [
        '@wvb/electron',
      ],
    },
  },
});
```

## Electron Builder

웹뷰 번들을 [Electron Builder](https://www.electron.build/)와 함께 사용하기 위한 사용법을 가이드합니다.

[`@wvb/electron-builder`](/docs/references/api/electron-builder)를 사용하면 웹뷰 번들 빌트인 번들을 앱 리소스에 복사할 수 있습니다.

<Tabs items={["npm", "yarn", "pnpm"]}>
  <Tab value="npm">
    ```sh
    npm install --save-dev @wvb/electron-builder
    ```
  </Tab>
  <Tab value="yarn">
    ```sh
    yarn add -D @wvb/electron-builder
    ```
  </Tab>
  <Tab value="pnpm">
    ```sh
    pnpm add -D @wvb/electron-builder
    ```
  </Tab>
</Tabs>

이후 기존 설정을 `withWebviewBundle`로 감싸세요:

```ts title="electron-builder.config.ts"
import { withWebviewBundle } from '@wvb/electron-builder';

export default withWebviewBundle({
  appId: 'com.example.app',
  asar: true,
  asarUnpack: ['**/*.node'],
});
```
